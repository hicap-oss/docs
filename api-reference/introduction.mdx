Use Hicap's OpenAI-compatible request format with a compatible SDK or an HTTP client. Set the base URL to **https://api.hicap.ai/v1** and send your Hicap key in the **api-key** header. Supported features depend on the endpoint, model, and your connection's configuration; OpenAI compatibility does not mean every upstream API feature is available.

## Authentication

Create a key in the [Hicap Platform](https://platform.hicap.ai/). Keep it on your server in `HICAP_API_KEY` or a secrets manager. Never put it in browser code, a public environment variable, or a request tag.

```bash
curl https://api.hicap.ai/v1/chat/completions \
  -H "api-key: $HICAP_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-5",
    "messages": [{"role": "user", "content": "Hello, world"}]
  }'
```

Bearer authentication alone does not authenticate a Hicap request. When an OpenAI SDK requires an `apiKey` setting, also configure the `api-key` request header as shown in the [quickstart](/quickstart).

## Supported endpoints

Use the endpoint for the operation you need:

| Operation | Method and path | Reference |
| --- | --- | --- |
| Public model list | `GET /v1/models` | [Models](/api-reference/models) |
| Text, image understanding, and tools | `POST /v1/chat/completions` | [Chat completions](/api-reference/chat-completions) |
| Embeddings | `POST /v1/embeddings` | [Embeddings](/api-reference/embeddings) |
| Image generation | `POST /v1/images/generations` | [Images](/api-reference/images) |
| Transcription | `POST /v1/audio/transcriptions` | [Transcriptions](/api-reference/audio-transcriptions) |
| Audio translation | `POST /v1/audio/translations` | [Translations](/api-reference/audio-translations) |
| Speech generation | `POST /v1/audio/speech` | [Speech](/api-reference/audio-speech) |

The model list is public and does not require a key. Inference routes require authentication. A model appearing in that list does not establish support for every endpoint or feature, or access under every connection.

### Endpoint availability

Image editing, Responses, Realtime sessions, and legacy Completions are also registered on the public gateway. Their request formats and model capabilities differ; use a compatible model and endpoint rather than assuming all chat parameters apply.

Image variations and stored Chat Completions retrieval are not included in the documented endpoint set. Do not assume those operations are available from OpenAI's API documentation.

## Versioned workflow operations

The Assistants and Threads and Vector Stores sections in the API Reference navigation describe operations registered on the public gateway.

Include the required `api-version` query parameter shown in each operation’s Query Parameters section. For example:

```bash
curl "https://api.hicap.ai/v1/assistants?api-version=2025-01-01-preview" \
  -H "api-key: $HICAP_API_KEY"
```

Many workflow routes require `api-version` for the gateway to match the operation. Omitting it can return `404 Resource not found` even when the method and path are otherwise correct. Use resource IDs returned by the corresponding create operations. Version, model, and connection compatibility still apply to backend execution.

## Models

Use an exact ID from the [public model list](/api-reference/models). The [model catalog](https://hicap.ai/models) supplies pricing and context information. If the catalog and API list differ, confirm the ID with support before depending on it; do not silently substitute a model.

For chat requests, text and image support, tools, structured output, sampling parameters, and token limits vary by model. A provider's native API may offer features that are not exposed through Hicap's compatible endpoint.

## Streaming

Set `stream: true` for server-sent events. Use streaming when required by your selected model or route; response handling must match the request.

```bash
curl -N https://api.hicap.ai/v1/chat/completions \
  -H "api-key: $HICAP_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-5",
    "messages": [{"role": "user", "content": "Write a haiku"}],
    "stream": true
  }'
```

Chat completion events contain incremental content; the stream normally ends with `data: [DONE]`. Handle HTTP errors before reading the stream and handle interruptions without assuming a complete answer.

## Attribution

Structural usage rolls up from your key. Add descriptive dimensions through one `x-hicap-tags` header containing a flat JSON object of string values. See [Tags, Dimensions & Segments](/concepts/tags-dimensions-segments) for tagging and coverage guidance.

## Rate limits

Limits depend on your plan, connection, reserved capacity, and selected backend. A reservation does not mean unlimited requests or unrestricted bursting. On `429`, honor `Retry-After` when present and use bounded exponential backoff with jitter. Check budgets and limits before retrying repeatedly.

Rate-limit and reset headers vary by route and backend; clients must handle their absence. Contact [support](mailto:support@hicap.ai) for your workload's limits and capacity options.

## Errors

Check the HTTP status first. Gateway errors and provider errors can use different bodies; do not require one JSON shape for every failure.

| Status | Typical meaning |
| --- | --- |
| `400` | Invalid body or unsupported parameter |
| `401` | Missing or invalid Hicap key |
| `403` | Access or policy restriction |
| `404` | Unknown route, resource, or model |
| `429` | Rate, capacity, or policy limit; inspect the response |
| `500` / `503` | Gateway or backend failure; retry only within a bounded policy |

An authentication failure at the gateway can return:

```json
{
  "statusCode": 401,
  "message": "Access denied due to invalid subscription key. Make sure to provide a valid key for an active subscription."
}
```

Other failures can return an OpenAI-style `error` object. Error text is diagnostic information; avoid logging credentials, prompts, or sensitive response content.

## Request IDs

Record a request/correlation ID when the response provides one, together with UTC time, endpoint, model, and status. An `x-request-id` header is not guaranteed on every response, including authentication failures. Share these details with support without including your API key or sensitive request content.

## Compatibility

Use the documented Hicap endpoint and selected model's supported parameters. Verify streaming, tools, response formats, and retry behavior when migrating an existing integration. Keep SDK upgrades and model changes reviewable rather than assuming complete compatibility with every OpenAI API operation.
