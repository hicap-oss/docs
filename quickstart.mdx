A model response is the beginning. Set up Hicap so you can trace AI usage to the workflow that generated it and measure what that workflow completed.

Start with three prompts: connect the client, add attribution, and track business outcomes. Hicap provides a shared API for supported models; use a compatible SDK with the Hicap base URL and required `api-key` header.

## Set up with an agent

Open your application repository in your coding agent, then run these three prompts in order. Each links to the full, maintained instructions.

### 1. Configure the client

Get your requests to the right place. Route supported model calls through Hicap and verify client configuration.

```text wrap title="Client setup"
Read https://docs.hicap.ai/onboarding-prompts/configure-client and help me set this up.
```

[Review the full client setup prompt](/onboarding-prompts/configure-client).

### 2. Add attribution

Give the bill some context. Identify the feature, operation, and other applicable dimensions behind each request, then verify the outgoing tags.

```text wrap title="Attribution"
Read https://docs.hicap.ai/onboarding-prompts/attribution and help me set this up.
```

[Review the full attribution prompt](/onboarding-prompts/attribution).

### 3. Connect business outcomes

Measure what got done. Define actual workflow outcomes and connect them to AI usage through your application's existing tracking. A generated support summary does not mean the case was resolved.

```text wrap title="Business outcomes"
Read https://docs.hicap.ai/onboarding-prompts/business-outcomes and help me set this up.
```

[Review the full business outcomes prompt](/onboarding-prompts/business-outcomes).

You'll need an API key from the [Hicap Platform dashboard ↗](https://platform.hicap.ai/). Keep it in server-side configuration; do not paste it into a prompt.

## Manual client setup

Prefer to configure the client yourself? Follow the examples below, then use the attribution and business outcomes prompts to add attribution and outcome tracking.

### 1. Get your API key

<Note>
  **Opens the Hicap Platform** — You'll create an account and generate an API key in the [Hicap Platform dashboard ↗](https://platform.hicap.ai/). Then come back here to use it.
</Note>

Keep the key on your server. Export it as an environment variable; never put it in browser code or a public environment variable:

```bash
export HICAP_API_KEY="your_api_key_here"
```

### 2. Install an SDK and make your first request

Use this fictional support case to check the connection. The examples use `gpt-5`; confirm model availability and endpoint support for your key before running them. A live request consumes usage.

<Tabs>
  <Tab title="JavaScript">
    ```bash
    npm install openai
    ```

    ```javascript example.mjs
    import OpenAI from "openai";

    const client = new OpenAI({
      baseURL: "https://api.hicap.ai/v1",
      apiKey: process.env.HICAP_API_KEY,
      defaultHeaders: { "api-key": process.env.HICAP_API_KEY },
    });

    const response = await client.chat.completions.create({
      model: "gpt-5",
      messages: [{ role: "user", content: "Summarize this support case in one sentence: A customer was charged twice for one order. Support confirmed the duplicate charge; a refund is pending." }],
    });

    console.log(response.choices[0].message.content);
    ```

### 3. Check what the response proves

A successful response proves the connection worked for this request. It does not yet prove that every application workflow uses Hicap, that its usage is attributed, or that the support case was resolved.

For this example, inspect the summary: it should preserve the fact that the refund is pending. Then use the [attribution prompt](/onboarding-prompts/attribution) to identify the support feature and summarization operation in your actual application. Use the [business outcomes prompt](/onboarding-prompts/business-outcomes) to track the workflow's agreed completion event from its source of truth.

## Changing the model is easy. Knowing you should takes evidence.

Compare models on the same representative support cases. Check whether each preserves the facts, how long a usable result takes, and what the completed workflow costs. Confirm support for your endpoint, tools, streaming, and other required parameters before switching.

The cheapest token can produce the most expensive result. Retries, extra model calls, and human corrections all affect the economics. Track AI cost per completed outcome and human review effort separately; token price alone cannot tell you whether a workflow is cheaper.

Choose an exact model ID from [the models endpoint](/api-reference/endpoints/openAI/lists-available-models), and use the [model catalog](https://hicap.ai/models) to compare options.

## Add capabilities when the workflow needs them

Keep the first integration small. Add image input when a support case includes a screenshot, or streaming when showing a partial answer helps the person waiting.

- **Images:** Follow the [chat completions reference](/api-reference/endpoints/openAI/creates-a-completion-for-the-chat-message) for request structure and confirm that the selected model supports image input.
- **Streaming:** The first token isn't the finish line. Measure time to a usable result and track interrupted responses alongside time to first token. See the [streaming guide](/api-reference/introduction#streaming).
- **Other endpoints:** Use the [API reference](/api-reference/introduction#endpoints) to find the request shape for your workflow, then verify model and endpoint compatibility.

## Make one real workflow explain its bill

Run a workflow you recognize. Check which model calls it made, which feature and operation they belong to, and what the workflow actually completed.

A response proves the model answered. Attribution tells you where the usage belongs. An outcome record tells you whether the work got done.

Before expanding, verify one workflow from request to result:

1. **Trace the requests.** Confirm which calls reach Hicap, including retries and follow-up calls. Record paths that remain elsewhere or are unverified.
2. **Inspect fresh attribution.** Select the right application, environment, and time window in Hicap. Check the expected feature, operation, and other applicable dimensions; older traffic retains its original tags.
3. **Check the actual outcome.** Use the application's agreed source of truth. A support summary is an intermediate result; case resolution needs its own evidence.
4. **Reconcile the cost.** Compare usage and completed outcomes for the same workflow scope and reporting window. Account for failed attempts and retries. Report missing data as unavailable, and avoid dividing by zero when no outcomes have completed.

Start with one workflow you can explain from request to result. Expand from there.
