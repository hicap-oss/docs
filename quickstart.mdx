Set up Hicap to route model requests, attribute usage to your application, and define the business outcomes you want to measure. Hicap provides a shared API for supported models using a compatible SDK and the `api-key` header.

You'll need a Hicap API key from the [Hicap Platform dashboard](https://platform.hicap.ai/) and access to your application repository. Keep the key on your server; don't paste it into an agent prompt.

## Set up with an agent

Open your application repository in your coding agent, then run these four prompts in order. The identity prompt assesses user, organization, tier, and trigger context independently; omit fields that don't apply. Each prompt links to its full instructions.

### 1. Configure the client

Route supported model requests through Hicap and verify the client configuration.

```text wrap title="Client setup"
Read https://docs.hicap.ai/onboarding-prompts/configure-client and help me set this up.
```

[Review the full client setup prompt](/onboarding-prompts/configure-client).

### 2. Set up base attribution

Identify the feature, operation, and other relevant dimensions for each request, then verify the outgoing tags.

```text wrap title="Attribution"
Read https://docs.hicap.ai/onboarding-prompts/attribution and help me set this up.
```

[Review the full attribution prompt](/onboarding-prompts/attribution).

### 3. Add identity attribution

Assess the initiating user and any applicable organization, tier, and trigger context. Users-only apps need no organization; apps without personal tiers omit tier. Verify identity propagation with synthetic data, and use production identifiers only when their handling is approved and verified.

```text wrap title="Identity attribution"
Read https://docs.hicap.ai/onboarding-prompts/identity and help me set this up.
```

[Review the full identity prompt](/onboarding-prompts/identity).

### 4. Connect business outcomes

Use the established dimensions and applicable identity to identify business questions, custom dimensions, and segments worth measuring. Connect costs to outcomes only when the required data and contracts are verified.

```text wrap title="Business outcomes"
Read https://docs.hicap.ai/onboarding-prompts/business-outcomes and help me set this up.
```

[Review the full business outcomes prompt](/onboarding-prompts/business-outcomes).

## Manual client setup

Prefer to configure the client yourself? Follow the examples below, then use the base attribution, identity, and business outcomes prompts to extend the setup.

### 1. Get your API key

<Note>
  **Opens the Hicap Platform** — You'll create an account and generate an API key in the [Hicap Platform dashboard](https://platform.hicap.ai/). Then come back here to use it.
</Note>

Keep the key on your server. Export it as an environment variable; never put it in browser code or a public environment variable:

```bash
export HICAP_API_KEY="your_api_key_here"
```

### 2. Install an SDK and make your first request

Use this fictional support case to check the connection. The examples use `gpt-5`; confirm model availability and endpoint support for your key before running them. A live request consumes usage.

<Tabs>
  <Tab title="JavaScript">
    ```bash
    npm install openai
    ```

    ```javascript example.mjs
    import OpenAI from "openai";

    const client = new OpenAI({
      baseURL: "https://api.hicap.ai/v1",
      apiKey: process.env.HICAP_API_KEY,
      defaultHeaders: { "api-key": process.env.HICAP_API_KEY },
    });

    const response = await client.chat.completions.create({
      model: "gpt-5",
      messages: [{ role: "user", content: "Summarize this support case in one sentence: A customer was charged twice for one order. Support confirmed the duplicate charge; a refund is pending." }],
    });

    console.log(response.choices[0].message.content);
    ```

    Run with `node example.mjs`.
  </Tab>
  <Tab title="Python">
    ```bash
    pip install openai
    ```

    import os
    from openai import OpenAI

    client = OpenAI(

### 3. Check what the response proves

A successful response proves the connection worked for this request. It does not yet prove that every application workflow uses Hicap, that its usage is attributed, or that the support case was resolved.

For this example, check that the summary says the refund is pending. Then use the [attribution prompt](/onboarding-prompts/attribution) to identify the feature and operation in your application. Use the [business outcomes prompt](/onboarding-prompts/business-outcomes) to identify the agreed completion event and its source of truth.

## Use evidence to choose the right model

Compare models on the same representative tasks. Measure output quality, time to a usable result, model cost, retries, and human review effort. Confirm support for your endpoint, tools, streaming, and other required parameters before switching.

When reliable cost and outcome records are available, compare AI cost per completed outcome and human review effort for the same workflow and reporting period.

Choose an exact model ID from [the models endpoint](/api-reference/endpoints/openAI/lists-available-models), and use the [model catalog](https://hicap.ai/models) to compare options.

## Add capabilities when the workflow needs them

Keep the first integration small. Add image input when a support case includes a screenshot, or streaming when showing a partial answer helps the person waiting.

- **Images:** Follow the [chat completions reference](/api-reference/endpoints/openAI/creates-a-completion-for-the-chat-message) for request structure and confirm that the selected model supports image input.
- **Streaming:** Measure both time to first token and time to a usable result. Track interrupted responses separately. See the [streaming guide](/api-reference/introduction#streaming).
- **Other endpoints:** Use the [API reference](/api-reference/introduction#endpoints) to find the request shape for your workflow, then verify model and endpoint compatibility.

## Verify one workflow end to end

Run a workflow you recognize. Check which model calls it made, which feature and operation they belong to, and what the workflow actually completed.

A successful response confirms that the request worked. Attribution helps you see where usage belongs. An outcome record shows whether the work was completed.

Before expanding, verify one workflow from request to result:

1. **Trace the requests.** Confirm which calls reach Hicap, including retries and follow-up calls. Record paths that remain elsewhere or are unverified.
2. **Inspect fresh attribution.** Select the right application, environment, and time window in Hicap. Check the expected feature, operation, and other applicable dimensions; older traffic retains its original tags.
3. **Check the actual outcome.** Use the application's agreed source of truth. A support summary is an intermediate result; case resolution needs its own evidence.
4. **Reconcile the cost.** When complete, comparable records are available, compare usage and completed outcomes for the same workflow scope and reporting window. Account for failed attempts and retries. Report missing data as unavailable, and avoid dividing by zero when no outcomes have completed.

Start with one workflow you can explain from request to result. Expand from there.
