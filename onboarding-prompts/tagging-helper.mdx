Follow the implementation prompt below in the user's application repository. Read the repository instructions before making changes.

````text wrap title="Tagging helper"
Add one small shared Hicap tagging helper. First inspect the whole application's
clients and request/process paths, tracing shared callers and queued/retried work;
report existing tags, merge precedence and gaps with file:line evidence.

The gateway is https://api.hicap.ai/v1; use server-side HICAP_API_KEY in the
`api-key` header. Every model request has one `x-hicap-tags` header containing
one JSON object of string values. Never expose keys, personal data or prompts.
Assess exactly agent/env/system/feature/domain: agent is a logical AI automation
(not a user/SDK); env is verified deployment config (NODE_ENV alone is insufficient);
system is the stable service; feature is the caller's business capability; domain
is broad business/industry context, never DNS. Industry examples commerce,
healthcare and financial_services are proposed defaults, not evidence. Do not
invent clinical or financial workflows from a template. Report evidence and
unknown/not-applicable states for all five; send only resolved strings, never null.
Use a non-agent sentinel only after documenting compatibility with consumers.
Preserve safe existing extra dimensions; do not invent new ones or silently
rename/delete legacy values. Distinguish ordinary requests from actual AI calls.

Merge service defaults, safe existing tags and explicit reviewed per-call context
in a documented order. Validate lowercase snake_case keys and short string values.
Handle header names case-insensitively; replace rather than append the header,
and reject/report malformed input safely. Never mutate a shared client's headers
per request or trust incoming client tags to override server-owned context. Pass
context across helpers/queues/retries, preserving different features per caller.
Route all compatible model calls through the helper; list deferred paths and why.
Test serialization, invalid values, precedence, existing extras, privacy and
concurrent isolation. Do not send paid requests. Keep ordinary traffic untouched,
document helper usage and report zero model calls if that is what the scan found.

Report two layers for all five dimensions: observed state with evidence, then
concrete recommended setup with config source, adoption step and check. An
unknown observed value is not an empty recommendation. Propose local-only
HICAP_ENV=development, explicit staging=staging and production=production;
preview=preview requires platform-context confirmation. These are proposed
config entries, not detected values or automatic NODE_ENV runtime fallbacks.
Give source-supported system/domain recommendations and exact config locations
when known; keep an unused client unused when no AI calls exist.

Write this step's findings to Markdown under the application's repository-root
.hicap directory (never filesystem root). Inspect/reuse existing tagging
examples/conventions first; if none exists, say so and use
.hicap/tagging-report.md. Preserve all existing files and human notes; if the
destination exists, write a timestamped sibling instead of overwriting it.
Include schema/version, UTC timestamp, source revision and applied/proposed
status, then sections: Scope and evidence; Observed attribution; Recommended
configuration; Request and process mapping; Implementation coverage; Validation
and open decisions. Include all five dimensions, source lines, concrete env
setup, ordinary-versus-AI paths, test results and deferrals. Do not claim
proposed tags were emitted. Verify the file exists/readable, link it from the
README when updating docs, and return its exact relative path.

Acceptance checks for affected paths: reject duplicate JSON dimension keys
(including escaped-equivalent keys), not only repeated HTTP headers. Show
trusted producer persistence, serialization, consumer restoration and retry
re-enqueue for resolved feature/agent/domain; keep unknowns explicit. Tests
must run a failing attempt then a successful retry and inspect separately
captured contexts/headers, not compare a value with itself. Report deferred
integration honestly; never force an unsupported provider migration.
````
