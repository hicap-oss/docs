Use this focused prompt when different model calls need distinct feature, operation or named role values. The agent traces the actual callers and checks their outgoing tags, including applicable retries or queues.

This prompt uses existing Hicap routes and does not change routing. Configure a [Hicap client](/onboarding-prompts/configure-client) first.

The block below includes the task and its shared contract for your coding agent. Review both before use, then review the agent's changes and verification report. For the overall workflow, see [Set up Hicap with a coding agent](/concepts/implement-attribution-with-an-agent).

````text wrap title="Implementation prompt"
Repair caller-specific attribution on existing Hicap-bound model workflows. Trace
product routes, grading modes, workers, jobs, scripts and fallbacks to the final
HTTP request. Reuse named pipeline roles from source even when the application
does not call that mode "multi-agent". Preserve the caller's business feature and
trigger through shared clients, fan-out, retries and queues; keep concurrent calls
isolated. Do not replace every workflow's feature with the helper's step name.
List every deferred or untested path and genuinely non-applicable dimension.

Before making changes, read and apply the complete versioned shared contract at
https://docs.hicap.ai/onboarding-prompts/focused-attribution-contract-v1.
If it is unavailable, stop and report the missing prerequisite; do not infer or
skip its safety and verification requirements. Record the contract revision or
content hash in the report, or state that provenance could not be verified.
````
