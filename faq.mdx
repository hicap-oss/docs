## Using Hicap

<AccordionGroup>
  <Accordion title="What does Hicap do?">
    Hicap connects your application to AI models through a shared API and provides controls and reporting for usage and spend. Start with the [quickstart](/quickstart), then choose a model from the [catalog](https://hicap.ai/models).
  </Accordion>
  <Accordion title="What do I need to change in an existing integration?">
    Set the base URL to `https://api.hicap.ai/v1`, configure your server-side Hicap key in the `api-key` header, and select an available model ID. Bearer authentication alone is insufficient. Verify the endpoint, model parameters, streaming, tools, and error handling your application uses; not every upstream API feature is interchangeable. See [API compatibility](/api-reference/introduction#compatibility).
  </Accordion>
  <Accordion title="Can I keep using other providers or an existing gateway?">
    Yes. Configure Hicap as an upstream destination in your existing gateway or router, with the Hicap base URL and `api-key` header. Hicap routes supported requests to configured model backends and provides its own connection-level governance. Your application's separate routing rules still determine which requests it sends to Hicap.
  </Accordion>
  <Accordion title="Which models are available?">
    Check the [public API model list](/api-reference/models) for exact model IDs and the [catalog](https://hicap.ai/models) for pricing and context information. Availability and supported features can change. A provider's native capabilities do not guarantee the same features through every Hicap endpoint.
  </Accordion>
</AccordionGroup>

## Capacity and pricing

<AccordionGroup>
  <Accordion title="How does reserved capacity differ from pay-as-you-go?">
    A reservation commits capacity and pricing under your agreement; pay-as-you-go charges for usage without that reservation. Plan limits, connection policies, and backend capacity still apply. Reserved capacity does not mean unlimited requests, automatic unlimited bursting, or the absence of overage charges.
  </Accordion>
  <Accordion title="How much can I save?">
    Savings depend on the models, usage pattern, capacity commitment, and agreement. Compare your workload's quoted rates with the [published model pricing](https://hicap.ai/models). Contact [support](mailto:support@hicap.ai) for a workload-specific quote.
  </Accordion>
  <Accordion title="What happens if I exceed my reservation or a limit?">
    Behavior depends on your connection policies, available backend capacity, and agreement. Requests can be limited or rejected; additional capacity or billing may require an arrangement. Plan bursts with support and handle `429` responses using bounded retries. See [rate limits](/api-reference/introduction#rate-limits).
  </Accordion>
  <Accordion title="Is there a minimum commitment?">
    Commitment length, cancellation, and scaling terms depend on the selected plan or agreement. Confirm the applicable terms before reserving capacity.
  </Accordion>
</AccordionGroup>

## Data and security

<AccordionGroup>
  <Accordion title="What happens to the data in my requests?">
    Hicap processes requests and forwards inference content to the selected model backend. Account, usage, billing, diagnostic, and inference-content data can have different handling requirements. Confirm the deployed logging configuration, model provider's policies, and applicable data-processing terms for your workload. Do not assume zero retention across all routes or providers from API compatibility alone.
  </Accordion>
  <Accordion title="Does my data go to third parties?">
    Model providers and service providers can process data as needed to deliver the service. Review the applicable processing terms, provider selection, and any residency or retention requirements before sending sensitive data. Contact [support](mailto:support@hicap.ai) for details relevant to your deployment.
  </Accordion>
  <Accordion title="How should I protect credentials and sensitive content?">
    Use HTTPS, keep API keys in server-side configuration or a secrets manager, and rotate keys when necessary. Do not include secrets or personal identifiers in attribution tags. Confirm required encryption, logging, access, and retention controls for the selected deployment rather than assuming one configuration applies everywhere.
  </Accordion>
  <Accordion title="What compliance documentation is available?">
    Request current security and compliance documentation for the service and deployment you plan to use. An API integration or configuration option does not by itself establish SOC 2 certification, GDPR compliance, or suitability for a regulated workload.
  </Accordion>
  <Accordion title="How do I request deletion or report a security concern?">
    Contact [support@hicap.ai](mailto:support@hicap.ai) with the account and request details, without including credentials or sensitive inference content. Applicable deletion, retention, incident-response, and notification obligations depend on the relevant terms and agreement; see the [Terms of Service](https://hicap.ai/terms).
  </Accordion>
  <Accordion title="Can I use a private or customer-cloud deployment?">
    Discuss deployment options with support. Confirm supported models, network paths, processing locations, logging, and provider dependencies for the proposed design. A component running in your cloud account does not by itself keep every inference request inside that account.
  </Accordion>
</AccordionGroup>

## Usage and attribution

<AccordionGroup>
  <Accordion title="How do requests appear under my application?">
    The key identifies its Connection and Application, so structural usage rolls up automatically. For labels such as feature, agent, and environment, send request tags. See [Applications, Connections & Keys](/concepts/applications-connections-keys) and [Tags, Dimensions & Segments](/concepts/tags-dimensions-segments).
  </Accordion>
  <Accordion title="Why can traffic still appear as Unattributed?">
    A selected dimension may be missing even when other tags are present. Distinguish a missing known role, a dimension that does not apply, unresolved configuration, old traffic, and an ingestion or display problem. Verify new requests after deployment in the matching application and environment. Changing a helper does not backfill historical tags.
  </Accordion>
  <Accordion title="Can an agent help set this up?">
    Use the short instruction in [Implement attribution with an agent](/concepts/implement-attribution-with-an-agent). The maintained prompt asks the agent to inspect real workflows, implement attribution, and verify final outgoing headers with mocked model responses.
  </Accordion>
</AccordionGroup>
